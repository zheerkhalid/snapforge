# Decisions

Each entry records a choice that the spec left open, or a place where the build departs from the spec, and why.

1. **`windows` 0.58 pinned.** The API is stable and well understood. Newer versions changed handle and `Option` signatures throughout. We will upgrade in one dedicated pass.
2. **eframe uses the `glow` (OpenGL) backend, not wgpu.** It starts faster and adds about 4 MB less to the binary.
3. **The editor runs on its own thread** (winit `with_any_thread`). The Win32 UI thread (tray, hotkeys, overlays) stays independent of the egui event loop, so cold start never pays for OpenGL initialization. The editor is created on first use, then hidden on close and shown again via `ShowWindow`, so later opens are instant.
4. **The PrtSc override runs a low-level keyboard hook on a dedicated thread.** It is never on the UI thread, so a busy UI can never stall system-wide keyboard input. Other hotkeys use `RegisterHotKey`.
5. **SFTP uses the OpenSSH client built into Windows** (`sftp.exe`, Windows 10 1809+) in batch mode with key-based authentication. A pure-Rust SSH stack would add several MB plus an async runtime. Plain FTP is a small built-in client (passive mode).
6. **OneNote:** its COM API needs page-XML plumbing, so OneNote output copies the image to the clipboard and activates OneNote. Word, Excel and PowerPoint use real COM automation (`IDispatch`).
7. **Passwords** (FTP) are stored encrypted with Windows DPAPI (per user), never in plain text in the TOML file.
8. **The app icon is drawn as vector art at build time** (`build.rs` + tiny-skia), so the repo has no binary icon assets and the branding is fully original.
9. **Capture overlays use a frozen screenshot.** The screen is captured first and the overlay paints that image, so menus and tooltips stay capturable and the selection shows exactly what will be saved.
10. **SnapForge's own windows use `WDA_EXCLUDEFROMCAPTURE`** (toolbar, countdown, scrolling indicator, recording bar), so they never show up in captures.
11. **Popup menus are tracked with `TPM_RETURNCMD`, owned by the tray's hidden top-level window** (`tray::menu`). The tray and the toolbar share one menu builder and dispatcher. After a menu closes, focus goes back to the window that was in the foreground, so "Capture Active Window" from a menu still targets the user's window.
12. **The PrtSc hook masks swallowed Win/Alt combos** by injecting an unassigned key (VK 0xE8), like AutoHotkey does. Without it, releasing Win would open the Start menu, and releasing Alt would activate the focused window's menu bar. A plain PrtSc also uses the hook, so Windows does not open the Snipping Tool.
13. **Toolbar rendering:** tiny-skia draws into a 32-bit DIB back buffer. Icons are rendered once per size and theme into premultiplied BGRA DIBs and composited with `AlphaBlend`. Only the delay badge digits use GDI text. Auto-hide polls the cursor every 100 ms, and only while the toolbar is docked, shown and the cursor is outside its client area. The slide animation timer runs only while the toolbar moves.
14. **Clipboard images are written three ways:** CF_DIBV5 (32-bit BI_BITFIELDS, straight alpha, bottom-up for compatibility), CF_DIB (24-bit composited over white, for apps that misread 32-bit DIBs) and the registered "PNG" format (transparency for Office and browsers). Pasting prefers PNG, then DIBV5, then DIB; a 32-bit DIB whose alpha is all zero is treated as opaque.
15. **SFTP is key-only.** `sftp.exe` runs with `BatchMode=yes`, which disables password prompts, so a stored password is ignored for SFTP (a warning is logged). Passing passwords to OpenSSH would need an askpass helper and is left for later.
16. **FTP passive mode connects the data channel to the control connection's address**, ignoring the IP in the PASV reply (servers behind NAT often report a private address). EPSV is tried first.
17. **Printing scales the image to fit the printable area** (up or down), centred, aspect ratio kept, composited over white, with HALFTONE stretching.
18. **Scrolling capture starts at the top of the page by default.** It first scrolls up (and left, for `Both`) in 60-notch wheel bursts until the view stops moving, because users expect a "full page" capture to begin at the top. The **Start from the top of the page** setting turns this off; capture then starts at the current scroll position, which suits pages with lazy loading or scroll side effects. `Both` captures vertical columns and scrolls back up by the amount it moved down between columns. (Until 0.1.3 the capture always started at the current position.)
19. **Stitch mismatch policy: append after a separator.** When a new frame does not line up with the previous one (content changed unexpectedly), the whole frame is appended after a dashed red separator, so nothing is lost and the problem is visible. The scroll loop stops after three mismatches in a row. `MismatchPolicy::Stop` is available for callers that would rather reject the frame.
20. **While scrolling, the cursor rests on the scrollbar side of the target**, and the matcher ignores a margin of about 20 px at each edge across the scroll axis. Hover effects in the content then stay constant, and the moving scrollbar thumb can't break the row matching. Scroll frames are always grabbed without the cursor.
21. **Overlay painting is driven by a primitive list ("scene").** Each input rebuilds the list; only primitives whose rect or content changed are invalidated, plus the XOR of the old and new undimmed areas. WM_PAINT walks the update region's rectangles and composes each one in a reusable backbuffer (grown on demand, never screen-sized after the first paint) instead of one backbuffer sized to the bounding box of `rcPaint`, because the crosshair lines make that bounding box span the whole screen on every mouse move. The very first paint draws straight to the window: the window is shown DWM-cloaked, painted synchronously, then uncloaked, so no stale or blank frame is ever composed.
22. **The dimmed overlay background is computed straight into its DIB section**, using the same formula as `Image::dimmed`, split across threads together with the copy of the bright image. This skips one 33 MB allocation and copy at 4K. Both bitmaps are cached between overlays (`overlay::release_idle_resources` frees them).
23. **Overlay clicks complete on button release**, and right-click acts on release, so the matching up-event never reaches the window underneath once the overlay hides. In Region mode, clicking a window returns `Selection::Rect` with the window's rectangle. In WindowObject mode, `Selection::Window.hwnd` is the top-level window and `rect` is the chosen element. In ScrollPick mode, `hwnd` is the innermost child window (from `ChildWindowFromPointEx`), because scrolling needs the control itself.
24. **`fixed_index` is persisted once, when the overlay closes**, not on every wheel notch. Each `settings::update` spawns a save, and many overlapping saves would race on the temp file.
25. **Capture backends: Auto uses DXGI when warm, GDI when cold, and WGC for HDR and for windows.** Measured on the dev machine (release build; 1920×1200 and 2560×1440 SDR monitors). The machine was busy with parallel builds, so treat these numbers as upper bounds. Full primary monitor, in ms: GDI cold 30–50, warm 30. DXGI cold 38–56 (device and duplication creation), warm 3–4. WGC cold 128–195, warm 30–32 (warm was about 130 before the WinRT item factory and monitor items were cached). Virtual screen (4480×1443): GDI 39–58; DXGI cold 61, warm 7–10; WGC cold 171–186, warm 47–81. WGC window grab: 19–32 ms. GPU resources are released after 10 s idle, so most hotkey presses are cold. Auto still captures therefore use GDI when no duplication is cached. They also warm DXGI in the background for the grabs that follow (scrolling, repeats, auto capture), and use DXGI first while it is warm. If the rect touches any HDR monitor, WGC goes first. Window captures always try WGC `CreateForWindow` first (it works when the window is covered), then fall back to grabbing the bounds. All GPU objects live on one MTA worker thread, which drops them after 10 s idle or on `release_idle_resources`. Driver DLLs stay loaded after release. In the test process, private bytes went from 2 MB at start to 54 MB warm, then 24 MB after release; the D3D user-mode driver accounts for the remainder.
26. **HDR → SDR tone mapping** (WGC, `R16G16B16A16Float`, scRGB):
    1. Divide by the monitor's SDR white level (`DISPLAYCONFIG_SDR_WHITE_LEVEL`, fallback 200 nits), so SDR content maps 1:1.
    2. Clip negative components (colors outside the sRGB gamut).
    3. Leave everything below a knee of 0.8 untouched. Above the knee, compress the max channel with an extended-Reinhard shoulder: slope 1 at the knee, exactly 1.0 at the frame's peak, peak capped at 64× SDR white. RGB are scaled together to keep the hue.
    4. Encode as sRGB.

    A frame with no HDR highlights converts exactly. DXGI duplication does not support rotated outputs; those fall back to GDI.
27. **The editor's event loop is created once and lives until exit.** winit cannot create a second event loop in one process, so closing the editor hides the window (`CancelClose` + `Visible(false)`). Other threads show it again with `ShowWindowAsync` + `SetForegroundWindow` (a hidden window gets no paint messages, so `update()` cannot do it), then `request_repaint()`. `ShowWindowAsync` never blocks the caller on the editor thread.
28. **Editor texture filtering is fixed per texture:** nearest-neighbour magnification, linear minification with mipmaps. This gives crisp pixels above 100% and smooth downscaling below it, without re-uploading when the zoom crosses 100%. Images are split into tiles of at most 8192 px (or the driver limit, if lower).
29. **Unnamed captures open as "dirty"** (never saved), so closing their tab asks Save / Don't Save / Cancel. Files opened from disk start clean.
30. **Editor Copy runs `clipboard::copy_image` on a worker thread**, because encoding the PNG clipboard format can take more than a frame for large images. This requires `copy_image` to work from any thread (`OpenClipboard(NULL)`, no delayed rendering).
31. **The Settings window is a deferred egui viewport, and Apply runs a three-way merge.** As a deferred viewport, it repaints on its own even while the editor's root window is hidden. The window edits a working copy. Apply merges it per value against the snapshot taken when the window opened: values the user changed win, and every other value comes from the live settings. So a toolbar drag, a file-name counter increment or a fixed-size preset change made while the window is open is never undone by OK. The window's size, position and last tab live in `ui_state.toml` in the settings folder, not in `settings.toml`.
32. **Exported settings files leave out the FTP password.** It is DPAPI-encrypted for one Windows user, so it is useless on another machine. On import, an empty password keeps the current one when the host and user name match. An import only fills the working copy; nothing changes until Apply or OK.
33. **"Auto Save" is the auto-capture page** (interval, mode, folder). The Output page holds the folder, format and quality used by every save, so these options are not shown twice. Sections without a dedicated page (recorder, print, and draw/pin/OCR/tools once they have fields) are edited generically from their serialized TOML fields. The labels come from `settings-field-<section>-<field>` keys when those exist.
34. **The hotkey box reads PrtSc by polling the key state, and it also offers a "Use PrtSc" button.** Windows sends no key-down message for PrtSc, egui has no PrtSc key, and SnapForge's own PrtSc hook may swallow the key. The box also polls the Windows key, because egui does not report it on Windows. Warnings cover duplicates, text that does not parse, and a list of Windows shortcuts. PrtSc combinations are left out of that list when the PrtSc override is on.
35. **Pin windows are `WS_POPUP | WS_THICKFRAME` with the non-client area removed in `WM_NCCALCSIZE` and a 1 px DWM frame extension**, which gives them the system shadow. Corners stay square and the DWM border is turned off. The pin paints its own 1 px accent border (amber in Draw Mode) *outside* the image, so the image pixels sit exactly at their captured screen position, 1:1 in physical pixels. `WS_EX_LAYERED` is added only while opacity is below 100%. `WM_DPICHANGED` updates only the chrome, never the image size.
36. **Draw Mode rasterizes each annotation into the pin's image as soon as it is committed** (pen stroke on release, text on Enter, step stamp on click). There is no object model; undo restores whole-image snapshots, capped at 256 MB in total (oldest dropped first). A canvas expand or crop is an undo step that also records the origin shift, so undo moves the pin back. Sizes (pen width, text height, stamp radius) are in image pixels, so annotations look the same at any zoom. Text uses GDI with grayscale anti-aliasing into a coverage mask, so it blends correctly on any background.
37. **Pin keys follow the spec literally: Esc closes the pin even in Draw Mode.** While typing text, Esc cancels the text, and Enter commits it instead of running the Enter action (Shift+Enter adds a new line). In Draw Mode a double-click draws instead of closing. Alt+drag (or the palette's grip) moves a pin in Draw Mode. The Draw Mode palette is an owned `WS_EX_NOACTIVATE` tool window, so keyboard focus stays on the pin. It is excluded from capture; the pin itself is not.
38. **OCR keeps the multithreaded apartment alive for the whole process (`CoIncrementMTAUsage`).** The `windows` crate caches WinRT activation factories in statics. When the first short-lived OCR worker exited, the MTA was torn down, and the next recognition crashed on the cached factory.
39. **OCR tiling for images larger than `OcrEngine.MaxImageDimension`:** tiles are spread evenly with an overlap of at least 400 px. Each word is kept only from the tile that owns its centre (ownership boundaries sit in the middle of each overlap). A second pass removes words with the same text and IoU > 0.5 from different tiles. Line fragments that a vertical tile edge split are joined again when they overlap vertically and the gap is under 2.5× the text height. Tiled results are ordered by rows (top to bottom), then left to right.
40. **OCR accuracy on small text:** images are composited over white first, because transparent pixels would read as black. Images with a side shorter than 40 px are upscaled before the first pass. If the median word height is under 20 px, or nothing is found, a second pass runs at 2× (3× under 10 px), and that result is kept if it finds at least as many words. Upscaling is skipped above 64 MP.
41. **The Capture Text window opens at once** with a "Recognizing…" status. A worker thread runs OCR (and lists the languages), stores the outcome in a shared slot and posts `WM_OCR_DONE`. A generation counter drops stale results after a language change. Choosing a language persists `settings.ocr.language`. Toggling "Keep line breaks" regenerates the text from the OCR result, so manual edits are discarded. The text area is a plain multi-line EDIT control (Segoe UI 10.5 pt, DPI-scaled), subclassed for Ctrl+A and Esc.
42. **Pin "Save As" uses the classic `GetSaveFileNameW` dialog** (no extra COM plumbing). The suggested name comes from `next_output_path`, which advances the file-name counter even if the dialog is cancelled. "Save and close" (Enter) saves straight to the next output path in the configured format.
43. **Effects work in premultiplied BGRA and are integer/fixed-point where it matters.** Resampling (Lanczos3, Mitchell, bilinear) is a separable two-pass convolution with 22-bit fixed-point weights, like Pillow, done in premultiplied space so transparent edges don't darken; after ringing filters, colour channels are clamped to alpha. All filters are deterministic on any thread count, so golden tests hold.
44. **Gaussian blur is three box-blur passes** (Kovesi's box sizes), O(1) per pixel whatever the radius, row bands on scoped threads. "Radius" follows CSS: sigma = radius / 2. Drop shadows, feathering, sharpening and the sketch smoothing all use it.
45. **Colour reduction is median cut on a 5-bit-per-channel histogram** (with exact per-bucket colour sums), split by range × population, then Floyd–Steinberg (serpentine) with a lazily filled 6-bit nearest-colour cache. Images that already fit the budget are returned unchanged. Alpha is kept; only RGB is quantised.
46. **Background removal measures the largest channel difference** (tolerance in percent). Smooth edges partially remove pixels just outside the tolerance and subtract the removed colour from them ("decontamination"), so anti-aliased text keeps clean edges on a new background. Contiguous mode floods 4-connected pixels and only softens pixels touching the flooded area.
47. **Oil paint is a Kuwahara filter** computed with running box sums of colour, luma and luma², in 32-row chunks per thread, so cost does not grow with the radius (1–15).
48. **Effect text uses GDI** (`effects::text::render_text`): white-on-black grayscale-antialiased text into a 32-bit DIB, the brightest channel as coverage, tinted afterwards. It matches the date stamp and needs no font crate. Wrapping uses `DrawTextW` with `DT_WORDBREAK | DT_EDITCONTROL`, so overly long words also break.
49. **Images to PDF uses `pdf-writer` 0.12** (plus `miniz_oxide`, already in the tree through `png`, for FlateDecode). It writes raw objects only; there is no layout engine and no fonts, adding ~100 KB. JPEG pages reuse `image`'s encoder (DCTDecode). Images are never enlarged beyond 96 DPI (0.75 pt per pixel), wide images get landscape pages in Auto mode, and long images are cut at quiet rows.
50. **Page splitting (PDF and batch print) cuts just below a blank row.** Each row's luma variance (over white) is computed; near each page boundary we look back up to a quarter page (never shrinking a page below half) for a row with variance ≤ 12, white rows first, then any uniform row. With no quiet row, the cut falls on the boundary. Every image in a batch print starts a new page, and images are loaded twice (plan, then print) so only one is in memory at a time.
51. **Torn edges are seeded** (`TornEdgeParams::seed`): alternating shallow/deep control points at irregular spacing plus fine fibre jitter, anti-aliased by perpendicular distance, with an optional light "paper fibre" rim and a soft shadow. Same seed, same edge, so previews and the applied result match.
52. **Screen tools read live pixels with GDI `BitBlt` from the screen DC** (`SRCCOPY | CAPTUREBLT`), not the Magnification API. Every tool window except the focus overlay uses `WDA_EXCLUDEFROMCAPTURE`, and BitBlt honours it (checked by the `tools::preview::bitblt_skips_excluded_windows` harness), so the magnifier and loupes never see themselves. Zooming is done in Rust (nearest or bilinear), which keeps the mapping testable and lets the lens be a round, per-pixel-alpha layered window.
53. **The click-through tools (crosshair, focus) get their input from low-level hooks** (`WH_MOUSE_LL` + `WH_KEYBOARD_LL`) on a dedicated thread that runs only while one of them is open. The hook swallows only what the tools own: Esc (closes the most recently opened tool), right-click while the crosshair is open, the wheel while the focus spotlight is open (Ctrl+wheel changes the dimming), and Ctrl+Shift+drag for the fixed focus rectangle. Mouse moves are coalesced to one pending message, so these tools need no polling timer.
54. **The crosshair is four thin layered windows** (left, right, above and below the cursor, leaving a gap around it) that show sub-rectangles of two line DIBs painted once. Following the cursor costs four `UpdateLayeredWindow` calls and no repainting, instead of re-uploading a screen-sized per-pixel-alpha surface per monitor on every move.
55. **The focus overlay is one layered window per monitor** with a monitor-sized DIB filled once; each move rewrites only the old and new spotlight boxes and pushes that dirty rectangle with `UpdateLayeredWindowIndirect`. It is deliberately **not** excluded from capture, so the spotlight shows in screen shares and recordings.
56. **The color picker uses an invisible "catcher" window** (alpha 1, excluded from capture) over the virtual screen, so clicks and keys never reach the app underneath; the loupe is a separate click-through window. Space freezes: the catcher turns opaque and shows a frozen screenshot that the loupe samples from. Losing the foreground (Alt+Tab) cancels picking. "Decimal" is the 0xRRGGBB value in decimal; "Delphi" is a `TColor` (`$00BBGGRR`).
57. **Ruler calibration is stored per monitor as a diagonal in inches**, keyed by GDI device name plus resolution (`\\.\DISPLAY1@2560x1440`), so a different panel on the same output does not inherit it. Without a calibration, the size the driver reports (`GetDeviceCaps` HORZSIZE/VERTSIZE, from the EDID) is used when plausible (4"–120", aspect ratio within 15% of the pixel grid), else 96 PPI. The ruler keeps its physical length when moved to a monitor with another DPI; thickness and text follow the new DPI.
58. **The native tool dialogs (color fine-tune, calibration) subclass their controls for Esc, Tab and Enter**, because the app's message loop has no `IsDialogMessage`. Tool settings that change continuously (format, prefix, suffix, zoom, sizes) are persisted when the tool closes, not per keystroke or wheel notch (see #24).
59. **Annotation text uses DirectWrite glyph outlines, not cosmic-text.** DirectWrite lays the text out (wrapping, alignment, font fallback, bidi, underline) and `GetGlyphRunOutline` turns each glyph into a vector path that tiny-skia fills. That gives outlines, shadows, and text on arcs and paths for free, and Segoe UI Emoji color layers come from `TranslateColorGlyphRun`. It costs nothing in binary size (system DLL), while cosmic-text would add about 1–2 MB and still need a separate color-emoji path. The trade-off is no hinting at small sizes, which is fine for annotations. Fonts are never bundled.
60. **Raster tools (blur, pixelate, eraser, fill, pencil) apply to the base image, under all vector objects**, in list order, but stay objects, so they remain editable and undoable. The editor keeps the result in `draw::RasterCache`, which re-applies only from the first changed raster object, so drawing a pencil stroke does not recompute earlier ones.
61. **Live view = effective base + a transparent overlay layer at the view's zoom.** Objects that read what is under them (multiply highlighters, blur/dim outside) composite the effective base into the layer beneath themselves, so the composited live view matches the exported image (tested). The magnifier samples the effective base, not other annotations.
62. **`.sfcap` is a zip** (`zip` crate, deflate via the flate2 already in the tree, no zopfli/bzip2/zstd/aes) with `original.png` (stored), `annotations.json` (`{"version":1,"objects":[...]}`) and `metadata.json`, written atomically. Inserted images are embedded in the JSON as base64 PNG. Readers ignore unknown fields and refuse newer annotation versions.
63. **Undo stores diffs, not snapshots.** An object edit records the id order before and after, plus only the added, removed or changed objects. Pixel edits store before/after base images as shared `Arc`s. History is unlimited. Image bytes in objects are `Arc`-shared, so diffs that touch them stay cheap.
64. **Editor undo stores swap patches, not commands.** Each step keeps only the changed rectangle's previous pixels, or the whole previous image when the size changed. Undoing a step swaps those pixels with the current ones, and the swapped-out pixels become the redo step. Raw steps above a per-document budget (`editor_ext.undo_raw_mb`, default 384 MB) are compressed on a worker thread as lossless fast PNG, using the `image` crate already in the build, so no new dependency. Only the most recent undo and redo steps stay raw unless they alone exceed the budget. Beyond `undo_total_mb` (default 1536 MB) the oldest steps are dropped, so "unlimited" undo means unlimited within that cap. Restoring a compressed step decodes on a worker while the document reports `busy()`. Phase 3 annotation layers record `StepKind::Overlay` markers so Ctrl+Z walks one timeline.
65. **The document "dirty" flag compares content states.** Every edit gets a fresh state id, undo and redo restore earlier ids, and a save records the id it wrote. Undoing back to the saved state therefore makes the tab clean again.
66. **egui reports Ctrl+V only when the clipboard holds text.** The editor therefore also watches the V key with `GetKeyState`, edge-triggered, so image pastes work. Clipboard reads run on a worker thread.
67. **Every menu item, ribbon button, shortcut and palette entry is a registered `Command`.** Shortcuts are matched exactly (no extra modifiers), because egui's `consume_key` would treat Ctrl+Shift+Z as Ctrl+Z. Keyboard access to commands goes through the command palette (Ctrl+K) rather than Alt-key menu mnemonics, which egui 0.31 cannot open programmatically.
68. **Effects plug in through `editor::register_effects`.** It takes an installer that edits the `EffectRegistry` table: id, menu slot and group, parameter schema and a pure apply function. Placeholder entries keep the Image and Effects menus complete until then. Their dialog opens with a preview, but Apply is disabled. Previews run on a ≤720 px box-filtered proxy in a debounced worker (120 ms). The final apply runs on a worker and commits one undo step, limited to the selection when the effect's scope allows it.
69. **Scanning uses `IWiaDevMgr2::GetImageDlg` on its own STA worker thread**, owned by the editor window, so the editor keeps painting while the WIA dialog is up. A batch scan reopens the dialog until the user cancels it. Deskew, white-border auto-crop and auto contrast/gamma are local and pure (`editor/scan_post.rs`). They run on the worker thread.
70. **Moving a selection leaves the editor's background colour behind** (`editor_ext.background`, default white). A move plus its drop is one undo step. The pre-move pixels are rebuilt from the saved source rectangle, so the history stores only the rectangle the move touched.
71. **Recorder threading.** Each recording runs on its own threads: video capture (`rec-video`), one WASAPI thread per audio source, a mixer, and the encoder. The encoder uses two writer threads, one per stream, around a single `IMFSinkWriter`, because with throttling on, the sink writer can block `WriteSample` on the stream that runs ahead until the other one catches up. The control bar, the region frame, the F5 hotkey and the click hook run on a separate `rec-ui` thread with its own message loop, so the app's UI thread is never involved while recording. Queues are bounded. The capture thread never blocks: when the video queue is full, the frame is dropped and counted.
72. **A/V sync uses one QPC media clock.** Video frame `k` has the timestamp `k/fps` on a constant-rate grid. When a slot is dropped, the next frame starts where the last one sent ended, so the stream has no gaps. Audio is placed on a 48 kHz timeline by each packet's WASAPI QPC position. The mixer runs 100 ms behind real time, fills gaps with silence (loopback delivers no packets while the system is silent), and drops or pads when a device clock drifts more than 15 ms. Pausing removes the paused time from the clock. On stop, the end time is rounded up to a frame boundary, so both streams end together. Measured A/V drift at the end of a 10 s recording: 14.7 ms, which is the AAC frame padding.
73. **Crash recovery uses fragmented MP4 plus a journal.** While recording, the sink writer uses `MFTranscodeContainerType_FMPEG4` and writes `<name>.recording.mp4`, with fragments of about 300 ms. A JSON journal in `<settings dir>\recordings\` records the partial and final paths. A clean stop remuxes the file into a regular MP4 without re-encoding. `recover_pending()` cuts a crashed file after its last complete `moof`+`mdat` pair, then remuxes it. If the remux fails, the truncated fragmented file is kept, because it is still playable. The MF fMP4 sink writes no `tfdt`, and the MF reader then guesses fragment start times wrongly by a few frames, so the remux rebuilds sample times from the durations. This is exact, because the streams are gapless (entry 26). WMV (ASF) and MP3 files are streamable as written, so recovery only renames them.
74. **Video path: GPU conversion, then a system-memory sample.** WGC (DXGI duplication as the fallback) is copied on the GPU into a mirror texture. The idle screen produces duplicate frames from that mirror. Direct2D draws the region or the animated zoom rectangle, the cursor, the click rings and the webcam into the output canvas. The D3D11 video processor converts the canvas to NV12 (BT.709, limited range). The NV12 frame is read back (a `Map` that never blocks while holding the device lock) and sent to the hardware H.264 MFT as a memory sample. Zero-copy DXGI samples (`MFCreateDXGISurfaceBuffer`, `IMFDXGIDeviceManager`, tracked-sample texture pool) are implemented. They are off by default (`recorder.zero_copy_gpu`) because they deadlocked intermittently on the test machine (Intel UHD). The read-back path costs about 22% of one core at 1080p60 in a debug build.
75. **MP3 uses the Windows MP3 encoder MFT, not LAME.** Windows 8 and later ship an MP3 encoder MFT, so MP3 recording and audio extraction need no extra crate or C build. `mp3lame-encoder` stays the fallback if a Windows edition lacks the MFT (N editions with the Media Feature Pack missing also lack H.264 and AAC).
76. **B-frames are off** (`CODECAPI_AVEncMPVDefaultBPictureCount = 0`). This keeps latency low and makes decode order match presentation order inside fragments.
77. **Scheduled recording has an API, not its own dialog.** `settings.recorder.schedule` holds one one-shot schedule (start and end in local time, the target, and sleep afterwards). `recorder::schedule::start_watcher()` checks it once a second. The settings window edits it through `schedule::set`, `schedule::validate` and `schedule::cancel`, so no extra native dialog is needed. A start missed while the PC was off still starts, as long as the end time has not passed. After the file is finalized, sleep uses `SetSuspendState`.
78. **Recorder targets.** "Full screen" records the monitor under the cursor. A region is clamped to the monitor that holds its centre. The region can be dragged during recording by its frame window, and follow-mouse moves it. A window target uses WGC window capture and follows the window as it moves. The output size is fixed at the start, rounded down to even dimensions. Recording across several monitors at once is not supported.
79. **`windows-core` is now a direct dependency.** The `#[implement]` macro, used for the COM callbacks `IMMNotificationClient` and `IMFAsyncCallback`, requires it. It was already in the dependency tree, so it adds no size.
80. **Video edits are stored in source time; the output timeline is derived.** Kept segments, zoom keyframes, title-card anchors and annotation `Timing` are all source milliseconds. `video_editor::timeline::build` turns segments plus title cards into the output sequence and maps between the two clocks. Cutting a range therefore never shifts an annotation or zoom away from the content it belongs to. Title cards are anchored at the start, the end, or "before source time t"; if t was cut, the card sits before the next kept frame. Undo snapshots the whole `EditState` (it is small, and inserted images are `Arc`-shared), coalescing a drag or a run of typing into one step.
81. **The video editor has its own small Media Foundation reader and writer (`video_editor::mf`).** The recorder module was written in parallel, so the two will be merged later. Decoding tries a D3D11 device with an `IMFDXGIDeviceManager` and `MF_SOURCE_READER_ENABLE_ADVANCED_VIDEO_PROCESSING` (hardware decode plus GPU conversion to RGB32) first, then falls back to software `ENABLE_VIDEO_PROCESSING`. Encoding goes through `IMFSinkWriter` with `MF_READWRITE_ENABLE_HARDWARE_TRANSFORMS`; if hardware setup fails it is retried in software. RGB32 input is marked top-down (`MF_MT_DEFAULT_STRIDE = width × 4`), which a test checks. H.264 output is rounded to even sizes. Audio is decoded to 16-bit PCM at 48 kHz stereo (the source reader resamples) and re-encoded to AAC at 192 kbit/s for the kept segments, with silence under title cards. Audio that AAC can't take is dropped with a log warning.
82. **Frames are composed in one order everywhere:** raster annotations (blur, pixelate) on the source frame, then the zoom rectangle cropped and scaled (fixed-point bilinear) to the output size, then vector annotations drawn at output resolution with `draw::render_overlay`, using a view onto the zoom rectangle. Zoomed-in text and arrows stay sharp, and the preview uses the same mapping, so it matches the export. Zoom keyframes are reached at their time, eased in over their transition (cubic ease-in-out, scale interpolated geometrically), and then held. Before the first keyframe the whole frame shows.
83. **Preview playback reads a frame cache that a decoder thread fills.** The UI never waits on a decode. The cache holds display-ready `ColorImage`s (sources wider than 1920 px are scaled down for preview) within a 384 MB budget. It keeps 0.4 s behind the playhead and 0.6 s ahead (1.5 s while playing). Read-ahead follows the kept segments across cuts. When decoding falls behind, the newest earlier frame stays on screen and the decoder skips ahead instead of stalling. Thumbnails and the waveform (one peak per 10 ms) come from two more worker threads. Preview audio plays through WASAPI shared mode with `AUTOCONVERTPCM`, using PCM kept in memory (up to 40 minutes). Its clock is the wall clock, and device start-up time is skipped, so there is no drift correction on long previews.
84. **GIF export uses the `gif` crate plus our own quantizer, not gifski.** `gif` 0.14 is already compiled in for `image`, so it adds no code. gifski would add libimagequant (GPL-3 or commercial licence), rayon and its own encoder pipeline, roughly 1 MB. Each frame gets a median-cut palette (`effects::build_palette`, see #45) and optional serpentine Floyd–Steinberg dithering. Only the rectangle that changed since the previous frame is stored. Unchanged pixels in that rectangle become transparent (255 colours plus 1 transparent), and identical frames lengthen the previous frame's delay. Delays come from the frame clock in centiseconds, so they don't drift. Screen recordings change little from frame to frame, so most frames shrink to small patches.
85. **`.sfvid` projects are plain JSON**, written atomically: `{"app","version":1,"source","source_info","segments","titles","zoom","annotations"}`. Annotations are `draw::Object`s whose timing is in source time. Readers ignore unknown fields and refuse newer versions. If the stored source path is missing, a file with the same name next to the project is used.
86. **Annotations live in a `DocOverlay` (`editor::annot::DrawLayer`) on top of the editor document's pixels.** The base stays in the editor document, so effects, crops and their undo work exactly as before, and raster objects (blur, eraser, fill, pencil) apply to whatever the base is at render time. Each object edit is recorded twice: as an object diff in the layer's `draw::History`, and as a `StepKind::Overlay` marker in the editor history. Ctrl+Z walks the editor timeline and forwards markers to the layer, so pixel and object edits interleave correctly. A pixel edit after undone object edits clears the editor's redo branch; the layer's stale redo entries are then unreachable and dropped by its next edit. Live drags edit the objects directly and record one step on release; property-bar edits are coalesced until the pointer is released.
87. **All draw tools share one `DrawState` behind a mutex**, reached by 25 thin `CanvasTool`s (one per `draw::Tool`, so every tool gets a command, a palette entry and an F-key) and by the app (palette, properties bar, in-place text editor). Everything runs on the editor thread; the mutex only satisfies `Send`, and it is never locked re-entrantly.
88. **The live annotation view is one texture of the visible area at the canvas zoom** (physical pixels, capped at 4096 px per side), rendered with `draw::render_overlay` and re-rendered only when the objects, the base pixels (`Arc` identity) or the view change. With raster objects the layer also carries the effective base for that area. Text being edited in place is hidden from the render and shown in an egui text box at the object's position and zoom.
89. **Exports flatten on worker threads.** `Document::export_job` hands save, copy, print, pin and *Continue* a cheap snapshot (base `Arc`, cloned objects in a flattener closure, optional selection); the job thread flattens with `draw::render`. Saving an annotated image also writes `<name>.sfcap` next to it (falling back to `<settings>/autosave`), setting `draw.autosave_project`, default on.
90. **Effects on a freehand selection blend through its mask with `effects::apply_masked`** on the effect worker, then commit only the selection's bounds. Effects that need the canvas (make transparent, spotlight, strips, watermark) are sessions: a side panel plus canvas input, previewed on a ≤1400 px proxy by a worker, applied as one undo step. The clone stamp is a canvas tool whose stroke edits the pixels live and is recorded once on release (`Document::live_pixels` / `end_live_edit`).
91. **Draw keys: F2–F12, Shift+F2–F12, Ctrl+F2/F3/F5, Tab / Shift+Tab** (see docs/USAGE.md). F1 stays the shortcut list, and the single letters already used by the editor (H, M, L, I, W, F, K, Z) stay as they are.
92. **The Settings window is hosted by the editor's eframe app, even when the editor window is hidden.** A hidden window gets no paint messages, so it runs no frames and could not open the Settings viewport; an off-screen window gets none either. To run one frame, the requester makes the hidden editor window an invisible, click-through tool window (layered, alpha 0, no taskbar button, not activated) and shows it in place; the frame opens the Settings viewport and hides the editor again. A first start for Settings alone uses the same trick for eframe's first-frame show. The Settings window's taskbar icon is set with `WM_SETICON` (big and small) from the exe's icon resource, because eframe only sets the small icon on child viewports.
93. **The editor follows the Settings theme** (System, Light or Dark) instead of always following Windows, so it matches the Settings window. The first-run window size is fitted into the monitor's work area with a 4% margin on every side (at least 16 px), and a saved placement larger than its monitor (after a DPI change) is fitted the same way. The ribbon wraps onto a second row on narrow windows, and the tool palette switches to two columns when it is too short for one.
94. **The video editor, Convert to MP4 and Schedule Recording are deferred viewports of the editor app, like Settings (#92).** `editor::open_video_editor`, `open_convert_to_mp4` and `open_schedule_recording` use the same invisible "ghost" frame, so opening them from the tray or the command line never shows the image editor. Combine, PDF and Batch Print stay windows inside the image editor because they work on its open tabs. `--open`, `editor::open_files` and drag and drop send videos (`.mp4`, `.wmv`, `.m4v`, `.mov`, `.avi`, `.mkv`) and `.sfvid` projects to the video editor, one file at a time, and images and `.sfcap` projects to the image editor.
95. **A notification can name a file (`AppCommand::Notify { file }`, `app::notify_file`).** Clicking the balloon opens a video in the video editor and reveals any other file in Explorer, or its folder if the file is gone. This replaces matching the balloon text against the "Saved to" message, which broke whenever the message changed. The "recording saved" balloon says that a click opens the video editor.
96. **Convert to MP4 resizes on the CPU and converts the frame rate by output slot.** The source reader's plain video processing cannot scale, and advanced processing needs a D3D device per conversion, so decoded NV12 frames are scaled with a 16.16 fixed-point bilinear filter, the Y plane and the interleaved UV plane separately. With a target frame rate, a decoded frame covering `[t, t + d)` fills every output slot `k` (time `k / fps`) not written yet whose time is before `t + d`. Downsampling therefore drops frames and upsampling repeats them, and the output rate stays constant. Without a target rate, the source timing is kept unchanged. With no explicit bit rate, the bit rate follows the recorder's quality formula at the output size and rate. Extract Audio uses `recorder::extract_audio` unchanged.
97. **The Schedule Recording window supersedes "no dialog" in #77.** It edits the same one-shot `settings.recorder.schedule` through `schedule::validate`, `set` and `cancel`. A new `ScheduleTarget::Window` stores a title, not a window handle, because handles do not survive a restart. When the schedule starts, the first window whose title matches exactly is recorded, otherwise the first whose title contains the text, ignoring case. If none matches, the full screen is recorded and a notification says so. Regions must be at least 16 × 16 px.
98. **Localization scope.** Everything in the tray, the toolbar, notifications, the overlay and the egui windows comes from `locales/*/main.ftl`. The command-line help (`--help`), the `--bench` report and log messages stay English: automation and support use them, and a translated report would be harder to compare. `CaptureError` keeps its English `Display` for the log; notifications map each variant to a message at display time (`controller::capture_error_text`). The old MessageBox About box was removed rather than translated, because Settings ▸ About replaced it.
99. **No crate-wide `#[allow(dead_code)]`.** Code that nothing calls was deleted. Helpers that only tests use are `#[cfg(test)]`. Re-exports list only what is reached through them. The hand-edit watcher for `settings.toml` was removed with the "open the settings file" stopgap: it could reload an older file over newer in-memory settings while a save was pending. An unreadable `settings.toml` is now reported once at startup (the file is kept as `settings.toml.bad`, as before).
100. **The bench measures recording like a user recording.** It runs `recorder::start_with` on the primary monitor (a region of at most 1920 × 1080) at 60 fps, with audio off and the control bar hidden. It skips the first 0.5 s (encoder start), measures 5 s, and reads the dropped and recorded frame counts from `status()`, then stops and deletes the file. CPU is the process's kernel + user time over wall time, reported as a share of all logical CPUs (the < 10 % budget) and of one core. An idle desktop mostly yields repeated frames; the report shows how many.
101. **Screen-tool commands toggle.** A screen-tool hotkey, toolbar button or tray entry opens the tool, or closes it if it is already open (`tools::toggle`).
102. **Tool size: one model for the slider, the keys and the wheel.** `editor/annot/size.rs` says which value is a tool's size (pen and stroke width, eraser radius, step stamp size, blur strength, font size of text), its limits and what the pointer shows (brush ring, stamp outline, a stroke-wide dot beside the crosshair). The slider is quadratic (`value = min + range × t²`), so small sizes get most of the track; the value field next to it still takes exact numbers. `[` and `]` are the size keys, as in most paint programs; `Alt+wheel` is the wheel gesture because `Ctrl+wheel` zooms and egui turns `Shift+wheel` into sideways scrolling (the plain wheel still resizes the eraser and the Clone Stamp, which have no use for scrolling while they paint). The slider, keys and wheel act on what the properties bar shows: the selected annotations if there are any (a burst of key or wheel steps is one undo step, closed by a 0.6 s pause or any other action), otherwise the tool. The system cursor is hidden only when the ring is at least 12 points wide; below that the crosshair stays, with the ring around it.
103. **Brush strokes are not selected after drawing.** Pencil, line highlighter and eraser strokes used to become the selection like every new object. The next stroke that started on top of the previous one then moved it instead of drawing, and the size controls resized the finished stroke together with the brush. The Select tool still selects strokes. Arrows, shapes, text and stamps stay selected after drawing, because their handles are used right away.
104. **After a scroll step, wait for the content to move before judging it.** Browsers apply wheel input a frame or more late and then animate the scroll. The loop used to take "two identical grabs 25 ms apart" as the result, so a late scroll looked like "the wheel does nothing": it switched to page scrolling, the late notch plus a whole page left no overlap, and two screens were joined by a red separator (seen in a real capture log). Now each step waits up to 800 ms for the frame to differ from the one before the step (more than 6 % of rows, or 120 rows, so a blinking caret does not count), then until three grabs 30 ms apart are identical. A step that never moves costs the 800 ms, which happens only at the end of the page.
