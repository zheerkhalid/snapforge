# Decisions

Each entry records a choice that the spec left open, or a place where the build departs from the spec, and why.

1. **`windows` 0.58 pinned.** The API is stable and well understood. Newer versions changed handle and `Option` signatures throughout. We will upgrade in one dedicated pass.
2. **eframe uses the `glow` (OpenGL) backend, not wgpu.** It starts faster and adds about 4 MB less to the binary.
3. **The editor runs on its own thread** (winit `with_any_thread`). The Win32 UI thread (tray, hotkeys, overlays) stays independent of the egui event loop, so cold start never pays for OpenGL initialization. The editor is created on first use, then hidden on close and shown again via `ShowWindow`, so later opens are instant.
4. **The PrtSc override runs a low-level keyboard hook on a dedicated thread.** It is never on the UI thread, so a busy UI can never stall system-wide keyboard input. Other hotkeys use `RegisterHotKey`.
5. **SFTP uses the OpenSSH client built into Windows** (`sftp.exe`, Windows 10 1809+) in batch mode with key-based authentication. A pure-Rust SSH stack would add several MB plus an async runtime. Plain FTP is a small built-in client (passive mode).
6. **OneNote:** its COM API needs page-XML plumbing, so OneNote output copies the image to the clipboard and activates OneNote. Word, Excel and PowerPoint use real COM automation (`IDispatch`).
7. **Passwords** (FTP) are stored encrypted with Windows DPAPI (per user), never in plain text in the TOML file.
8. **The app icon is drawn as vector art at build time** (`build.rs` + tiny-skia), so the repo has no binary icon assets and the branding is fully original.
9. **Capture overlays use a frozen screenshot.** The screen is captured first and the overlay paints that image, so menus and tooltips stay capturable and the selection shows exactly what will be saved.
10. **SnapForge's own windows use `WDA_EXCLUDEFROMCAPTURE`** (toolbar, countdown, scrolling indicator, recording bar), so they never show up in captures.
11. **Popup menus are tracked with `TPM_RETURNCMD`, owned by the tray's hidden top-level window** (`tray::menu`). The tray and the toolbar share one menu builder and dispatcher. After a menu closes, focus goes back to the window that was in the foreground, so "Capture Active Window" from a menu still targets the user's window.
12. **The PrtSc hook masks swallowed Win/Alt combos** by injecting an unassigned key (VK 0xE8), like AutoHotkey does. Without it, releasing Win would open the Start menu, and releasing Alt would activate the focused window's menu bar. A plain PrtSc also uses the hook, so Windows does not open the Snipping Tool.
13. **Toolbar rendering:** tiny-skia draws into a 32-bit DIB back buffer. Icons are rendered once per size and theme into premultiplied BGRA DIBs and composited with `AlphaBlend`. Only the delay badge digits use GDI text. Auto-hide polls the cursor every 100 ms, and only while the toolbar is docked, shown and the cursor is outside its client area. The slide animation timer runs only while the toolbar moves.
14. **Clipboard images are written three ways:** CF_DIBV5 (32-bit BI_BITFIELDS, straight alpha, bottom-up for compatibility), CF_DIB (24-bit composited over white, for apps that misread 32-bit DIBs) and the registered "PNG" format (transparency for Office and browsers). Pasting prefers PNG, then DIBV5, then DIB; a 32-bit DIB whose alpha is all zero is treated as opaque.
15. **SFTP is key-only.** `sftp.exe` runs with `BatchMode=yes`, which disables password prompts, so a stored password is ignored for SFTP (a warning is logged). Passing passwords to OpenSSH would need an askpass helper and is left for later.
16. **FTP passive mode connects the data channel to the control connection's address**, ignoring the IP in the PASV reply (servers behind NAT often report a private address). EPSV is tried first.
17. **Printing scales the image to fit the printable area** (up or down), centred, aspect ratio kept, composited over white, with HALFTONE stretching.
18. **Scrolling capture starts at the current scroll position.** It does not jump to the top first. The user chooses where the capture begins, and pages with lazy loading or scroll side effects are not disturbed. `Both` captures vertical columns and scrolls back up by the amount it moved down between columns.
19. **Stitch mismatch policy: append after a separator.** When a new frame does not line up with the previous one (content changed unexpectedly), the whole frame is appended after a dashed red separator, so nothing is lost and the problem is visible. The scroll loop stops after three mismatches in a row. `MismatchPolicy::Stop` is available for callers that would rather reject the frame.
20. **While scrolling, the cursor rests on the scrollbar side of the target**, and the matcher ignores a margin of about 20 px at each edge across the scroll axis. Hover effects in the content then stay constant, and the moving scrollbar thumb can't break the row matching. Scroll frames are always grabbed without the cursor.
21. **Overlay painting is driven by a primitive list ("scene").** Each input rebuilds the list; only primitives whose rect or content changed are invalidated, plus the XOR of the old and new undimmed areas. WM_PAINT walks the update region's rectangles and composes each one in a reusable backbuffer (grown on demand, never screen-sized after the first paint) instead of one backbuffer sized to the bounding box of `rcPaint`, because the crosshair lines make that bounding box span the whole screen on every mouse move. The very first paint draws straight to the window: the window is shown DWM-cloaked, painted synchronously, then uncloaked, so no stale or blank frame is ever composed.
22. **The dimmed overlay background is computed straight into its DIB section**, using the same formula as `Image::dimmed`, split across threads together with the copy of the bright image. This skips one 33 MB allocation and copy at 4K. Both bitmaps are cached between overlays (`overlay::release_idle_resources` frees them).
23. **Overlay clicks complete on button release**, and right-click acts on release, so the matching up-event never reaches the window underneath once the overlay hides. In Region mode, clicking a window returns `Selection::Rect` with the window's rectangle. In WindowObject mode, `Selection::Window.hwnd` is the top-level window and `rect` is the chosen element. In ScrollPick mode, `hwnd` is the innermost child window (from `ChildWindowFromPointEx`), because scrolling needs the control itself.
24. **`fixed_index` is persisted once, when the overlay closes**, not on every wheel notch. Each `settings::update` spawns a save, and many overlapping saves would race on the temp file.
25. **Recorder threading.** Each recording runs on its own threads: video capture (`rec-video`), one WASAPI thread per audio source, a mixer, and the encoder. The encoder uses two writer threads, one per stream, around a single `IMFSinkWriter`, because with throttling on, the sink writer can block `WriteSample` on the stream that runs ahead until the other one catches up. The control bar, the region frame, the F5 hotkey and the click hook run on a separate `rec-ui` thread with its own message loop, so the app's UI thread is never involved while recording. Queues are bounded. The capture thread never blocks: when the video queue is full, the frame is dropped and counted.
26. **A/V sync uses one QPC media clock.** Video frame `k` has the timestamp `k/fps` on a constant-rate grid. When a slot is dropped, the next frame starts where the last one sent ended, so the stream has no gaps. Audio is placed on a 48 kHz timeline by each packet's WASAPI QPC position. The mixer runs 100 ms behind real time, fills gaps with silence (loopback delivers no packets while the system is silent), and drops or pads when a device clock drifts more than 15 ms. Pausing removes the paused time from the clock. On stop, the end time is rounded up to a frame boundary, so both streams end together. Measured A/V drift at the end of a 10 s recording: 14.7 ms, which is the AAC frame padding.
27. **Crash recovery uses fragmented MP4 plus a journal.** While recording, the sink writer uses `MFTranscodeContainerType_FMPEG4` and writes `<name>.recording.mp4`, with fragments of about 300 ms. A JSON journal in `<settings dir>\recordings\` records the partial and final paths. A clean stop remuxes the file into a regular MP4 without re-encoding. `recover_pending()` cuts a crashed file after its last complete `moof`+`mdat` pair, then remuxes it. If the remux fails, the truncated fragmented file is kept, because it is still playable. The MF fMP4 sink writes no `tfdt`, and the MF reader then guesses fragment start times wrongly by a few frames, so the remux rebuilds sample times from the durations. This is exact, because the streams are gapless (entry 26). WMV (ASF) and MP3 files are streamable as written, so recovery only renames them.
28. **Video path: GPU conversion, then a system-memory sample.** WGC (DXGI duplication as the fallback) is copied on the GPU into a mirror texture. The idle screen produces duplicate frames from that mirror. Direct2D draws the region or the animated zoom rectangle, the cursor, the click rings and the webcam into the output canvas. The D3D11 video processor converts the canvas to NV12 (BT.709, limited range). The NV12 frame is read back (a `Map` that never blocks while holding the device lock) and sent to the hardware H.264 MFT as a memory sample. Zero-copy DXGI samples (`MFCreateDXGISurfaceBuffer`, `IMFDXGIDeviceManager`, tracked-sample texture pool) are implemented. They are off by default (`recorder.zero_copy_gpu`) because they deadlocked intermittently on the test machine (Intel UHD). The read-back path costs about 22% of one core at 1080p60 in a debug build.
29. **MP3 uses the Windows MP3 encoder MFT, not LAME.** Windows 8 and later ship an MP3 encoder MFT, so MP3 recording and audio extraction need no extra crate or C build. `mp3lame-encoder` stays the fallback if a Windows edition lacks the MFT (N editions with the Media Feature Pack missing also lack H.264 and AAC).
30. **B-frames are off** (`CODECAPI_AVEncMPVDefaultBPictureCount = 0`). This keeps latency low and makes decode order match presentation order inside fragments.
31. **Scheduled recording has an API, not its own dialog.** `settings.recorder.schedule` holds one one-shot schedule (start and end in local time, the target, and sleep afterwards). `recorder::schedule::start_watcher()` checks it once a second. The settings window edits it through `schedule::set`, `schedule::validate` and `schedule::cancel`, so no extra native dialog is needed. A start missed while the PC was off still starts, as long as the end time has not passed. After the file is finalized, sleep uses `SetSuspendState`.
32. **Recorder targets.** "Full screen" records the monitor under the cursor. A region is clamped to the monitor that holds its centre. The region can be dragged during recording by its frame window, and follow-mouse moves it. A window target uses WGC window capture and follows the window as it moves. The output size is fixed at the start, rounded down to even dimensions. Recording across several monitors at once is not supported.
33. **`windows-core` is now a direct dependency.** The `#[implement]` macro, used for the COM callbacks `IMMNotificationClient` and `IMFAsyncCallback`, requires it. It was already in the dependency tree, so it adds no size.
